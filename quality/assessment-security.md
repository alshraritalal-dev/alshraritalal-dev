# أمن بنك التقييم — الوضع الفعلي في V3.1.5

## نتيجة الفحص
- الموقع الحالي ملف HTML/JavaScript عام.
- مفاتيح الإجابات والقيم المتوقعة موجودة في البيانات والشيفرة التي تصل إلى المتصفح.
- تقدم الطالب محفوظ محليًا في المتصفح ويمكن للمستخدم تعديل localStorage.
- لا توجد قاعدة بيانات تقييم خاصة أو API خادمي لتصحيح أسئلة محجوزة.
- لذلك لا يمكن ضمان سرية أسئلة التقييم في هذه البنية.

## الإجراء المنفذ
- أُغلقت بوابة الإتقان برمجيًا: secureAssessmentAvailable=false.
- كل الأسئلة الحالية assessmentEligible=false.
- اختبارات النقل في الأكاديمية والمدرس أصبحت تدريبًا تكوينيًا، ولا تمنح شارة إتقان معتمدة.
- عقل رحلة لا يحتسب أي محاولة مستقلة إلا عند وجود اعتماد تحريري مستقل، وعائلة غير مكشوفة، وإثبات خادمي؛ كما يتطلب تفعيل خادم التقييم الخاص.
- جرى ترحيل حالات الإتقان القديمة غير المدعومة إلى حالة تدريبية/تحتاج متابعة مع إبقاء سجلات المحاولات وعدم حذفها.

## ما لا تعنيه هذه التغييرات
هذا إغلاق احترازي داخل الواجهة وليس نظام أمن خادمي. لا يجعل الأسئلة سرية، ولا يمنع تعديل المتصفح أو localStorage. لا تضع بنكًا سريًا أو إجابات اختبار حقيقي داخل HTML.

## شرط فتح التقييم لاحقًا
لا تُفعّل البوابة إلا بعد تنفيذ backend خاص، وتخزين أسئلة التقييم في قاعدة بيانات غير عامة، وإرسال السؤال للطالب دون answer key، والتحقق من الإجابة خادميًا، وربط المحاولة بمعرّف طالب/جلسة موثوق، ومنع إعادة العائلة المكشوفة، وتسجيل النتيجة الخادمية. راجع PRIVATE-ASSESSMENT-BACKEND-SPEC.md.
